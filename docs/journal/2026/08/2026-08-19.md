## What I learned

**The harness matters more than the model.** The thing I had been calling "the
AI tool" is really two separable pieces: a model that produces text, and a
program around it that runs the loop, executes tools, manages context and
enforces permissions. Two products on the same model can behave completely
differently. Written up in [What is an AI Harness?](/ai/agents/harness).

This reframes several things I was confused about — why upgrading the model
sometimes changes so little, and why most of what gets called prompt
engineering is really harness behaviour.

**Skills are how you extend a harness without modifying it.** A folder with a
Markdown file of instructions. The part I had not appreciated is progressive
disclosure: only the name and description stay in context, and the body loads
on demand, so having many skills is cheap. That makes the description the most
important field — a skill nobody can find does not exist. See
[What are Agent Skills?](/ai/skills/fundamentals).

**Which leads straight to SkillHub.** Once skills are files, they need the
things files always end up needing: discovery, versioning, provenance, and
some way to tell that one has gone stale. Started notes at
[SkillHub](/projects/skillhub/basic). Current instinct is a Git repository plus a
CLI, not a service — Git already gives history, review and distribution.

**Agentic SDLC clicked as a constraint, not a capability.** The question for
each lifecycle stage is not "can an agent do this" but "can I verify it faster
than I could do it myself". Stages with cheap checks — tests pass, types are
happy — work today. Stages without them produce plausible output that still
costs full attention to evaluate.

**Set up BaseBox.** This site. VitePress over a folder of Markdown, sidebar
generated from the filesystem so writing a note never means editing config.
